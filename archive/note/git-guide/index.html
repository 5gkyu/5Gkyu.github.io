Git 超入門ノート ── 4つの「場所」と基本コマンド
2026.07.20 ガイド
Gitって難しそう……エラーが出るとパニックになっちゃう。 大丈夫！基本の仕組みさえ分かれば、実は「ファイルのタイムマシン 兼 バックアップツール」でしかないんだ。ゲームのセーブデータみたいなものだよ。

Gitを使いこなす上で一番重要なのが、ファイルが今どこにあるかという4つの場所（状態）の理解です。

1. 4つの「場所」を理解しよう

① Working Directory（作業ディレクトリ）
あなたのパソコン上のフォルダ（現在作業している場所）です。ここでファイルを編集・保存します。

② Staging Area（ステージングエリア）
「次にセーブする（記録する）ファイル」を仮置きする荷造り用の箱です。

③ Local Repository（ローカルリポジトリ）
あなたのパソコン内にある自分専用の金庫です。（.git という隠しフォルダがこれです）ステージングエリアの箱がここに保存され、セーブデータ（履歴）として記録されます。

④ Remote Repository（リモートリポジトリ）
インターネット上（GitHubなど）にあるクラウドの保管庫です。パソコンが壊れてもここにあれば安心です。GitHub Pagesはここのデータを読み取ってWebサイトとして公開しています。

2. 普段の作業の流れ（基本の3ステップ）

ファイルを変更して、それをGitHubに反映するまでの基本の流れは以下の3ステップです。

① 荷造りする：git add

変更したファイルを「ステージングエリア（箱）」に入れます。

# 変更したすべてのファイルを箱に入れる（一番よく使います） git add . # 特定のファイルだけを箱に入れる場合 git add index.html

② 箱に名前をつけて金庫にしまう：git commit

箱を閉じて、「何を変更したか」というラベル（メッセージ）を貼り、パソコン内の金庫（ローカルリポジトリ）に保存します。

# -m の後に、変更内容のメモを書きます git commit -m "トップページのデザインを修正"

③ クラウドに送信する：git push

パソコン内の金庫に新しく追加されたセーブデータを、GitHub（リモートリポジトリ）に送信します。

# origin(GitHub) の main(メインブランチ) に送信する git push origin main

基本はこの add → commit → push の3つをセットで行うだけです！

3. その他の重要なコマンド

今の状態を確認する：git status

自分が今どのステップにいるのか、どのファイルが変更されたのかを確認するコマンドです。迷子になったらとりあえずこれを打ちます。

  • 赤色のファイル：まだ箱（add）に入っていない変更
  • 緑色のファイル：箱（add）に入っていて、金庫（commit）に入れる準備ができている変更

クラウドの最新状態をダウンロードする：git pull

別のパソコンで作業した時や、GitHub上で直接ファイルを編集した時に、その最新状態を自分のパソコンに取り込みます。

git pull origin main

4. GitHub Pagesとの関係

あなたのサイトは、GitHub（クラウド）の main ブランチにプッシュされたファイルを自動的に読み取ってWebサイトとして公開する仕組みになっています。そのため、ローカルのVS Codeでいくらファイルを編集して保存しても、git push をしてクラウドに送信しない限り、Webサイトには反映されません。

もしエラーでサイトが更新されなくなったら？
本日のトラブルのように、Jekyll（GitHub側のサイト構築システム）がエラーを起こすと、git push自体は成功していても、Webサイトの見た目が更新されなくなります。
その場合は .nojekyll というファイルを置いてJekyllを停止させたり、間違って入ってしまった .git フォルダを取り除くことで解決します。
