## 1. 全体アーキテクチャと基本仕様

### 1.1 基本スペック
* **総フレーム数**: 3,022 フレーム（フル尺 251.83 秒 / 約 4 分 11 秒）
* **フレームレート (FPS)**: 12.0 FPS
* **元動画**: `rag.mp4`（1080p, 15fps）
* **座標系**:
  * アスペクト比: `16 : 9`（横幅 $X = \pm 210.0$ / 高さ $Y = \pm 118.125$）
  * カラーパレット:
    * `0`: 背景グレー（`#B2B2B2` / RGB 178, 178, 178）
    * `1`: 純黒（`#000000` / 線画・黒髪・服・背景黒）
    * `2`: 純白（`#FFFFFF` / 白線画・白キャラクター・歌詞）

### 1.2 データ圧縮形式（RLE: Run-Length Encoding）
全3,022フレームのピクセルデータは、`[値, 連続数, 値, 連続数, ...]` のベクトル化 RLE 形式で圧縮格納され、展開時のメモリ消費とロード時間を最小化しています。

## 2. 空間別 Dual-Resolution（ハイブリッド解像度）設計

全体の「レトロなドット絵の質感」と「文字のクリアな可読性」を最高水準で両立するため、画面を空間的・時間的に分割するハイブリッド構造を採用しています。

```
+-------------------------------------------------------------+  gy: 0
|                                                             |
|           通常シーン上部: 320 x 160 (ドット絵解像度)        |
|               ※ マジョリティルールで白ノイズゼロ            |
|                                                             |
+-------------------------------------------------------------+  gy: 320
|==== 歌詞帯: 640 x 32 (倍密度高精細ドット) ===================|
+-------------------------------------------------------------+  gy: 352
|           通常シーン最下部: 320 x 4                         |
+-------------------------------------------------------------+  gy: 360
```

### 2.1 シーンごとの解像度切り替え
1. **通常シーン（空間別 Dual-Resolution）**:
   * **上部（gy: 0〜319）**: $320 \times 160$ のドット絵解像度。2×2ブロックのマジョリティ判定（白2点以上、または黒1点以上）により、エンコードノイズや不要な白点を完全排除。
   * **歌詞帯（gy: 320〜351）**: $640 \times 32$ の倍密度高精細ドット。漢字の微細な払いや跳ねを鮮明に再現。
   * **最下部（gy: 352〜359）**: $320 \times 4$ のドット絵解像度。
2. **全画面高精細シーン（640 × 360）**:
   * **1684〜1834 フレーム**: 自動改札機通過シーン（目・顔・服の微細線画を精密再現）
   * **2467〜2506 フレーム**: 特殊黒背景・白線画シーン（1〜2px の繊細なペン画をシャープに再現）
   * **2839〜2858 / 2879〜2898 / 2919〜3021 フレーム**: アウトロ・ラストシーン（粒子のフェードアウトまで高密度に描画）

## 3. 歌詞・線画抽出アルゴリズムの進化と知見

### 3.1 発生した課題と解決の変遷

| 課題 | 発生原因 | 解決アルゴリズム |
| :--- | :--- | :--- |
| **歌詞以外の背景や服が白化する** | 歌詞帯全体に一律で低い白閾値を適用していたため | **時空間限定マスク**: `kasi.txt` のタイムスタンプ区間 ＆ 実際の文字が存在する左右バウンディングボックス内のみに限定 |
| **特殊黒背景シーンの線が太い** | 3×3 膨張（dilate）と解像度不足（320x180） | **案A 高精細化**: 3×3膨張を撤廃し、`640x360` の倍密度グリッドで元動画本来の繊細な白線を 1 ドット幅で抽出 |
| **黒髪と重なる文字の線が細くなる** | 白文字（255）と黒髪（0）が縮小時混ざり合い、輝度が 120〜170（グレー）に落ち込む | **黒領域内ピンポイント線幅補正**: 黒髪内にある文字のみ最小 2 ドット幅を保証 |
| **関係のない黒線画の周囲が白化する** | 黒線画周囲の背景グレー（178）を白文字ストロークと誤認 | **文字芯束縛型抽出**: 白文字の芯（`gray >= 195`）に直接隣接する中間混ざり色（`80 <= gray <= 170`）のみを局所補正 |

## 4. 超軽量レンダリングエンジン（Direct Pixel Blit）

### 4.1 Direct Pixel Blit の仕組み
四角ドットは本質的に「グリッド上のピクセル」であるため、Canvas 2D の低レベルメモリ書き込みを活用して高速化しました。

```
[RLEマスターデータ]
        ↓ 高速デコード (0.05ms)
[Uint32Array ピクセルバッファ (640x360, 32bit ABGR)]
        ↓ putImageData (0.08ms)
[オフスクリーン Canvas (640x360)]
        ↓ drawImage (たった 1 回の全画面拡大描画 / 0.1ms)
[メイン Canvas (imageSmoothingEnabled = false)]
```

* **描画コスト**: 約 15ms $\to$ **0.2ms 以下（CPU 負荷 90% 削減）**
* **フレームレート**: 低スペック環境でも **60 FPS 張り付きの滑らかな動作** を実現。

## 5. リアルボーカル WAV ＆ 力強いベース ＆ 楽器ビルドアップ MIDI 合成システム

### 5.1 【リアルボーカル WAV ＋ リアルタイムMIDI伴奏】の完全ハイブリッド
* **ボーカル音源**: `sound/ラグトレイン_synth_vocal.wav`（24bit 48kHz フル尺ステレオ）
* **完全同期再生**: Web Audio の `MediaElementSourceNode` を経由し、空間リバーブ（Shimmer Reverb）やマスターコンプレッサーを介して MIDI 伴奏と完璧に調和。
* **力強いベースライン**: 三角波 ＋ サブオシレーターにより、420Hz〜550Hz の太く芯のあるパンチを強化（ゲイン 0.46）。

3. **✨ 星空オルゴール (楽器ビルドアップ)**: オルゴール ＋ グラスハープ ＋ 超広大 Shimmer リバーブ
